```bash
pip install -r requirements.txt
python solution_Дронов_ШАД-111.py
```

## Описание алгоритма

### Единицы анализа

* **Триггер аномалии:** `(SubjectID, researchdate, BrandID, CategoryDelivery)`.
* **Единица удаления:** `(SubjectID, researchdate)` — именно она попадает в `anomalies.csv`.
* Если респондент признан аномальным хотя бы по одному бренду за день, удаляется
  вся его активность за этот день.

### Агрегация OTS

Для строк поставки (`BrandinDelivery == 1`, непустой `CategoryDelivery`):

```
daily_ots(i, j, k) = Weight(i, k) * count_rows(i, j, k)
```

`count_rows` — число строк респондента по данному бренду и категории за день.
`Weight(i, k)` — дневной вес респондента; в данных встречается небольшой разброс
веса внутри респондент-дня (~1% случаев), поэтому берётся **медиана** веса по
респондент-дню (детерминированно и совпадает с формулой, когда вес постоянен).

### Что считается аномалией

Чрезмерно **высокий** `daily_ots` относительно  **исторического уровня самого бренда** .
Для каждого бренда строится эталонное распределение `L = log1p(daily_ots)` по всем
его наблюдениям `(респондент, день)` за период. Логарифм — потому что OTS
мультипликативен и сильно скошен; в логах внутрибрендовое распределение
приближённо симметрично, что корректно для модифицированного z-score.

**Сила аномалии (score):**

```
score = 0.6745 * (L − median_L) / MAD_L      (робастный modified z-score)
```

(Iglewicz & Hoaglin, 1993). MAD устойчив к выбросам, поэтому сами аномалии не
«раздувают» порог.

### Порог (threshold) — считается из данных, свой для каждого бренда

```
threshold = max( z(Q3 + 3·IQR),  3.5 )
```

`Q3 + 3·IQR` — «дальняя» ограда Тьюки (граница **экстремального** выброса, k = 3),
пересчитанная в те же z-единицы, что и score. Нижняя отсечка `3.5` — классический
порог modified z-score. Решение:  **аномалия ⇔ `score > threshold`** .
Оба критерия — общепринятые статистические константы, а не подобранные числа.

### Малые выборки и редкие бренды

Если у бренда меньше `N_MIN = 30` наблюдений, эталон берётся на уровне
`CategoryDelivery` (иерархический фолбэк). Если `MAD = 0` (вырожденное
распределение) — фолбэк на категориальный, затем глобальный MAD.

### Защита от удаления малого OTS

Дополнительное условие: `daily_ots ≥ глобальной медианы daily_ots`. Малый OTS
никогда не может стать причиной удаления — флагуются только большие значения,
крупные относительно своего бренда **и** в абсолюте.

### Почему подход разумен

* Работает **на уровне брендов** (эталон строится по каждому бренду), а не только
  по категории или общему OTS.
* **Интерпретируем:** у каждой аномалии есть `daily_ots`, `score`, `threshold` и
  текстовая причина.
* **Воспроизводим и детерминирован:** только медианы/квантили, никакой случайности,
  random_state не требуется; повторный запуск даёт тот же `anomalies.csv`.
* **Нет хардкода** ID/дат/брендов/целевого процента; все пороги — из данных или
  стандартные константы.
* **Устойчив:** при разбиении по месяцам и по категориям доля удалений остаётся в
  узком коридоре ~0.02–0.06% респондент-дней (≤2 в день) — она не зафиксирована
  вручную, а естественно следует из данных.

### Результаты на предоставленном датасете

59 триггеров → 59 пар `(SubjectID, researchdate)` (46 уникальных респондентов),
≈0.20% респондентов. Суммарный OTS сохраняется на  **98.94%** , при этом срезаются
экстремальные одиночные бренд-дневные пики; воздействие равномерно по дням и
категориям.

### Устойчивость к другому периоду (проверка на больший объём)

Все пороги (`median`, `MAD`, `Q3`, `IQR`, нижний пол OTS) пересчитываются из
поданных данных; работа в лог-пространстве делает метод инвариантным к масштабу
активности. Проверено эмпирически:

* **По месяцам** (объём растёт с 46.5k строк / 210M OTS в июне до 67.3k / 271M в
  октябре) доля удалений держится в коридоре **0.019–0.060%** респондент-дней и
  не растёт вслед за объёмом.
* **Масштабирование `daily_ots` ×2 / ×5 / ×10** (имитация «больше поисков и
  покупок») даёт практически идентичный результат: 59 → 58 удаляемых пар, те же
  ≈0.043%.
* При **росте базовой активности** эталонное распределение расширяется и метод
  становится консервативнее (меньше удалений), а не агрессивнее.

Доля удалений нигде не зафиксирована вручную — она естественно следует из данных,
поэтому на скрытом периоде с иным объёмом поведение остаётся корректным.

## Аналитические возможности (п. 8.2)

Функции вызываются без переписывания основной логики:

* `before_after_by_dimension(df, removed_pairs, dim_col, cnt=...)` — OTS до/после в
  любом разрезе: `Пол`, `Возраст`, `Регион`, `Федеральный_округ`, `ResourceName`,
  `ResourceType`, `Platform`, `UseType`, `CategoryDelivery`, `Category1/2/3`.
* `querytext_table(df, subject_id, date)` — таблица `QueryText` для выбранного
  аномального респондента и дня.
* `brand_ots_by_day(df, removed_pairs, brand_id, cnt=...)` — OTS по дням для
  выбранного бренда до/после очистки.

Несколько таких разрезов автоматически строятся в `output/plots/extra/` при запуске.

## Параметры (вверху скрипта)

`N_MIN = 30`, `MODZ_FLOOR = 3.5`, `TUKEY_K = 3.0` — статистически обоснованные,
не привязаны к результату.
